## 2. Tech stack & why

- **Static HTML/CSS/vanilla JS**, generated by a Node script (`build/build.mjs` + `build/site.mjs` + `build/content.mjs`) rather than hand-written per page. This keeps the header, footer, SEO tags, and shared sections consistent across all 22 pages — edit the data/template once, regenerate everything.
- **No React/Vue/framework.** The brief called for something that could run on cheap shared hosting; a framework would have added build complexity and weight for no real benefit on a marketing site with a contact form.
- **No PHP backend** (a `quote-handler.php` file exists as a documented fallback/alternative, but is **not** what's wired up — see §6).
- **Why Cloudflare Pages over traditional cPanel hosting:** free, faster (global CDN), automatic HTTPS, and — critically — supports **git-based auto-deploy**, which the client specifically wanted instead of manual FTP/dashboard uploads.

## 3. Brand & design system

Built entirely around the client's own logo colours — deep charcoal + the logo's signature amber-to-copper orange.

| Token | Value | Use |
|---|---|---|
| `--charcoal` | `#16130F` | Header, footer, dark section backgrounds |
| `--stone` | `#F6F2EB` | Page background |
| `--amber` / `--amber-bright` | `#F7931E` / `#FBB040` | Primary accent, CTAs, dark-section highlights |
| `--copper` | `#E2620E` | Secondary accent, light-section highlights, headings |

**Typography:** Fraunces (serif, headings) + Manrope (sans, body) — a premium/editorial pairing distinct from generic template fonts.

**Orange brand presence** (client-requested, iterated twice): first letter of every major H2 heading is coloured orange (e.g. "**S**ee the transformation"), section sub-headings/leads are copper/amber, CTA banner text is warm amber, footer headings (Services/Company/Get in Touch) and social icons are orange, chip/filter hover states turn orange, and text selection (`::selection`) highlights in brand amber.

**Logo:**
- Header/footer use the client's own **icon mark** (`vision-touch-mark.webp`, transparent PNG) + a **recoloured wordmark** built from the client-supplied "logo text.png" — original had dark-grey lettering that was invisible on the dark header, so it was recoloured to off-white with the original orange "V" and "T" preserved.
- Header shows a shorter "Vision Touch" wordmark (no "Ltd") per client request; footer shows the full "Vision Touch Ltd".
- **Animated 3D logo**: the header/footer icon has a CSS-only 3D entrance animation, a slow idle float/tilt, and a hover barrel-roll — done in pure CSS (no Framer Motion/React, to keep the site framework-free). **Fully reversible**: set `logoMotion: false` in `build/site.mjs` and rebuild to make it static again. Auto-disables for users with reduced-motion preference set.
- **Auztec Innovations logo** (client's own dev-credit logo, supplied separately) is used in the footer credit line and on the presentation deck's cover/closing slides — both link/attribute correctly.

## 6. Forms & integrations

### Enquiry form (Request a Quote + Contact)
- **Provider:** Web3Forms (free tier, 250 submissions/month, no card required)
- **Access key:** live and wired in `build/site.mjs` (`web3formsKey`)
- **Delivery:** submissions go to the email tied to the Web3Forms account — **client should confirm/update this in their Web3Forms dashboard to route to `inquiries@visiontouchltd.co.uk`** if it isn't already
- **Behaviour:** works with JS (inline AJAX submit, no page reload) and without JS (native form POST fallback) — enquiries are never lost either way
- **Spam protection:** two honeypots (a custom field + Web3Forms' own `botcheck`) plus full client-side validation and a required consent checkbox
- **Fields:** Name, Phone, Email, Location/Postcode, Service Required, Project Budget, Project Details, Consent. (**Preferred Contact Method field was removed** per client request — redundant since phone/email are already collected.)
- **Phone number display policy:** per client request, the raw phone number is **not printed anywhere** on the site as visible text — every instance is now a "Call Us" button (the number still lives inside the functional `tel:` link, so click-to-call still works)

### WhatsApp
- Floating WhatsApp button on every page, pre-filled message, `wa.me/447572222245` link
- Click-to-call buttons throughout (no visible number, per above)

### Google Map
- Keyless Google Maps embed on the About page (no API key/billing needed) showing Greater London with the borough/area chip list
- To recenter: get a fresh embed URL from Google Maps → Share → Embed a map, paste into `buildAbout()` in `build/build.mjs`

## 7. Deployment & hosting — how it all connects

```
Local edits (Z:\claude\vision-touch-website)
        │  git commit + git push
        ▼
GitHub — visiontouchltd/visiontouchweb (main branch)
        │  Cloudflare watches this repo
        ▼
Cloudflare Pages — runs `npm run cf-build`
        │  (regenerates HTML, assembles a clean /publish folder)
        ▼
Live at www.visiontouchltd.co.uk within ~1–2 minutes
```

**Cloudflare Pages project settings:**
- Project name: `visiontouchweb`
- Production branch: `main`
- Build command: `npm run cf-build`
- Build output directory: `publish`
- Framework preset: None

**Domain setup:**
- Domain purchased on **Namecheap**; nameservers switched to Cloudflare's (`frank.ns.cloudflare.com` / `kallie.ns.cloudflare.com`) — DNSSEC turned off at Namecheap to allow activation
- Both `www.visiontouchltd.co.uk` and the apex `visiontouchltd.co.uk` are added as custom domains on the Pages project, each with free auto-issued SSL
- A **redirect rule** (`apex to www`) sends `visiontouchltd.co.uk` → `https://www.visiontouchltd.co.uk` (301), matching the site's canonical URLs/sitemap

**What's excluded from the live deploy (`build/publish.mjs` handles this):**
- `build/`, `.claude/`, `node_modules/`, `README.md`, `package.json` — dev-only, not needed live
- `.htaccess` — Apache-only, irrelevant on Cloudflare (replaced by `_headers` for caching/security headers)
- `quote-handler.php` — not used (Web3Forms handles submissions instead)
- **`assets/presentation/`** — this folder holds client deliverables (the pitch deck, a 140MB demo walkthrough video) that are not part of the public website; also excluded from git entirely (`.gitignore`) since GitHub rejects files over 100MB

**Redeploying after future edits** (whether done via chat or manually):
```bash
node build/build.mjs      # regenerate all HTML from templates
git add -A && git commit -m "..." && git push
# Cloudflare auto-builds and deploys — no manual upload needed
```

## 8. Performance & SEO

- **Video compression:** source videos were originally ~480MB combined; compressed to ~15MB total (720p, muted, H.264, poster frames) — a ~97% reduction
- **Images:** WebP with JPEG fallback via `<picture>`, lazy-loaded below the fold, explicit width/height to avoid layout shift
- **CSS-driven animations** (scroll reveals, hover states, the coverflow carousel) — minimal JS (~20KB total across all scripts), no heavy libraries
- **SEO:** unique title/meta per page, canonical URLs, Open Graph/Twitter cards, `sitemap.xml` (22 URLs) and `robots.txt` pointing to the live domain, JSON-LD structured data throughout
- **Accessibility:** keyboard-navigable nav and carousels, visible focus states, ARIA labels, alt text on all images, reduced-motion support, skip-to-content link

**Still to do:** submit the sitemap to Google Search Console (`https://www.visiontouchltd.co.uk/sitemap.xml`) — instructions in README §8.

## 9. Reviews — current state & Google integration plan

Current reviews are **placeholder content** (realistic names, plausible text, not real). Discussed and recommended path to replace with live Google reviews:

1. Client sets up/confirms their **Google Business Profile**
2. Connect a free review-widget service — **Trustindex** or **Featurable** — to that profile (both have free tiers)
3. The widget auto-syncs new Google reviews onto the site on a refresh cycle (not manual, but not always instant on free tiers)
4. Paste the resulting embed snippet in — I'll drop it into the Reviews page (and optionally homepage), replacing the placeholder cards
5. Add a "Leave us a Google review" button/link so customers can easily add reviews

**Not yet actioned** — waiting on the client to set up the Google Business Profile / pick a widget provider.

- **Note:** these files are excluded from the live deploy and from git (see §7) — they exist locally only. If they need sharing, send them directly rather than via the site.

## 11. Chronological summary of major work

1. **Initial build** — full 22-page site, design system, all 11 service pages with bespoke copy, homepage sections (hero video, trust strip, process, before/after, projects, reviews, FAQs), quote/contact form (originally PHP + mailto fallback), SEO/schema/sitemap/robots.txt, README, and the 20-slide presentation deck.

4. **Google Map + Web3Forms migration** — added the About page service-area map; replaced the original PHP-mail/mailto form flow entirely with Web3Forms (client-requested, no backend needed); corrected the enquiry email domain typo (`visiontouch.co.uk` → `visiontouchltd.co.uk`) across the entire codebase.
5. **Real photography integration** — client supplied real before/after project photos and a folder of on-site "work in progress" photos; these replaced the original placeholder/stock imagery in the Before & After page, homepage teaser, and Projects page.
6. **Design polish round** — increased brand-orange presence throughout (orange initial letters on headings, orange sub-headings, orange footer headings/social icons, orange hover/selection states); rebuilt the reviews carousel with working dot indicators (previous buttons were dead — a CSS/DOM structure bug); built an Apple-style "See us at work" **coverflow carousel** with hover-driven depth; converted Projects-page cards from links (to the quote page) into an image **lightbox popup**; removed leftover legal-disclaimer boilerplate and a visitor-facing "demo reviews" caption that shouldn't have shipped.
7. **Coverflow refinement round** — fixed the carousel to loop **seamlessly** (previously empty space appeared at the first/last slide because offsets were linear, not circular), enlarged the display card size, then — per client aesthetic feedback — trimmed the gallery from 18 down to 12 photos (removing one genuinely low-resolution image plus five more by preference) and compacted the whole section (smaller arrows, tighter spacing) so it fits within a single viewport without scrolling.
8. **Domain identity fix** — corrected the site's configured domain from a placeholder to the client's real `visiontouchltd.co.uk` across canonical tags, Open Graph, sitemap, and robots.txt.
9. **Go-live** — repository initialised, pushed to GitHub (`visiontouchltd/visiontouchweb`), connected to Cloudflare Pages with an auto-deploy build pipeline (`npm run cf-build` → `publish/`), Namecheap domain migrated to Cloudflare nameservers, custom domain + SSL + apex→www redirect configured. **Site has been live and auto-deploying since this point.**
